## Purpose

Produces the high-quality keyframes that SparkVSR propagates across each shot, since the reference frames — not the model alone — determine how much real detail the restored video gains.

## ADDED Requirements

### Requirement: Selectable reference modes

The service SHALL support three reference generation modes — an in-service image super-resolution model, an external image restoration API, and no references — with the in-service model as the default.

#### Scenario: Default mode

- **WHEN** a caller submits a job without specifying a reference mode
- **THEN** references are generated by the in-service image super-resolution model

#### Scenario: External API mode without credentials

- **WHEN** a caller selects the external API mode and the required API credential is not configured
- **THEN** the request is rejected before any GPU work starts, with a message naming the missing credential

#### Scenario: Reference-free mode

- **WHEN** a caller selects the reference-free mode
- **THEN** processing proceeds with no reference frames and the model performs blind restoration

### Requirement: Reference frames match the output geometry

Generated reference frames SHALL have the same dimensions as the target output resolution.

#### Scenario: 4K target

- **WHEN** the job targets 3840x2160 output
- **THEN** each generated reference frame is 3840x2160

#### Scenario: Reference generation failure

- **WHEN** reference generation fails for a frame
- **THEN** the job fails with a diagnostic message rather than silently substituting an upscaled low-quality frame

### Requirement: Reference frames are cached per job

Generated reference frames SHALL be persisted for the lifetime of the job so a retried or resumed run does not regenerate them.

#### Scenario: Retry after a later-stage failure

- **WHEN** a job fails after references were generated and is retried
- **THEN** the cached reference frames are reused rather than regenerated

#### Scenario: Cached references are inspectable

- **WHEN** a job completes
- **THEN** the reference frames used are retrievable for inspection, so a caller can judge whether reference quality limited the result

### Requirement: Reference generation releases GPU memory

The in-service reference model SHALL be unloaded from GPU memory once all reference frames for a job are generated, before the main model runs.

#### Scenario: Reference generation completes

- **WHEN** all reference frames for a job have been generated by the in-service model
- **THEN** that model's GPU memory is released before super-resolution inference begins

### Requirement: Reference adherence is adjustable

The caller SHALL be able to control how strongly the output adheres to the reference frames.

#### Scenario: Default adherence

- **WHEN** a caller does not specify a reference guidance strength
- **THEN** the model runs a single forward pass per chunk

#### Scenario: Increased adherence

- **WHEN** a caller raises the reference guidance strength above the default
- **THEN** the output adheres more closely to the reference frames
- **AND** the caller is informed that this doubles inference compute per chunk
